## Implemented contract

- Service-only rehearsal authorization binds administrator, existing customer, product, exact draft or delivered release/cart digest, full release SHA, evidence and an initiation lifetime of at most 30 minutes. MATERIALS digests are SHA-256 of sorted lowercase match UUIDs joined by commas. Scoped live canary authorizations use a separate immutable resource binding.
- An authoritative singleton checkout mode defaults LOCKED. New initiation serializes against mode changes. Leaving LOCKED requires no unresolved initiation or provider-paid-but-unverified payment. Legacy begin/reopen entry-point service grants are revoked, preventing stale deployed instances from bypassing the mode gate.
- Both authorized begin RPCs atomically persist the existing quote/intent, command, payment, held reservation and durable initiation before any provider call. Exact retries return the same identities, provider key and 35-minute Session deadline. The authorization expiry is independent of that immutable provider deadline.
- Revoke, lock and authorization/deadline expiry request provider expiration without erasing history. Provider binding survives those races and preserves late paid accounting. Terminal unpaid provider reconciliation releases held capacity; paid observations never regress. Provider-paid attempts with unverified underlying payments remain in the service-only reconciliation selector and prevent unlocking.
- Crash-before-provider-create cleanup requires an exhausted provider listing covering the entire creation window, a durable matching sanitized audit receipt and at least five minutes beyond the Session deadline. Partial, failed, capped or receipt-less listings cannot prove absence. A late verified paid event still binds and enters the existing exact refund path.
- Newly activated search starts at provider payment time. New original material clocks start at the later of confirmed inputs and provider payment; processing time does not extend the customer's deadline. Existing stored payment/release/deadline records are not rewritten.

## Inherited defects found by real material checkout tests

The earlier fixture suite mostly constructed paid material records directly. The new fixture runs actual creation, promotion, payment, expiration and late-payment RPCs and exposed these blockers:

1. The 800-only unnamed material intent constraint survived alongside 052's named 799/800 constraint. 085 removes only the verified obsolete duplicate; current creation remains 799 and historical 800 records remain valid.
2. Checkout and current material release still required Arial, although 081 permits only Liberation Sans in configuration. 085 changes only those current gates, leaving version-specific historical artifact/download checks intact.
3. Search activation retains an immutable anonymous intake snapshot with `customer_id` NULL. Material creation now joins that exact snapshot to the customer's DELIVERED service and delivered order, preserving ownership without rewriting snapshot history. The first broader NULL-ownership proposal was automatically rejected; the implemented direct ownership joins passed review. Browser roles cannot insert/update the service ownership record.
4. A generic immutable revision trigger rejected the existing RPC's initial capacity binding and paid clock. A dedicated guard permits those one-time initializations only with exact capacity membership, customer/payment binding and verified clocks; revision content and already bound capacity/times remain immutable, with one-way supersession retained.
5. A generic immutable capacity-member trigger rejected paid consumption and delivery lifecycle updates. A dedicated guard keeps allocation/member/line/revision/unit identity immutable, requires paid consumed allocation for HELD-to-SPENT, requires immutable release for completion, and prevents spent capacity from being returned.
6. Material expiration skipped COMPENSATING, and paid fulfillment skipped APPLYING. Search NONE expiration had the same compensation error. 085 uses the existing permitted state-machine transitions. Repeated quote invalidation now skips already invalidated quotes instead of weakening quote immutability.

Independent delta review is required for these author-owned changes; this report is not that review.
