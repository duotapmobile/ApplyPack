Source basis: published candidate `9995b90ee13feb41de55a1a65e6496fff1735578` plus the subsequent uncommitted recovery implementation. - The fixed source API uses separate read, copy-completion, receipt-signing and retention capabilities. Only the web service holds the Supabase credential and receipt-signing secret. Requests cannot select arbitrary tables, columns, origins or queries. Completion requires two fresh signed source inventories from the same release, followed by a monotonic heartbeat update.
- Review found missing retention linkage for private render previews. The author added the finite `ap_artifact_quality_reviews` → file version → artifact graph, including expiry/revocation and unresolved-reference rejection. Review also found metadata/body reads could outlive their stated deadline; bounded-operation and body-read deadlines now cover them.
- Restore checks the latest complete object and reference allowlists before copying old archive versions. The current regressions exclude deleted legacy drafts, cleared references and replaced provider versions even where old code did not persist a tombstone. Restore leaves all target access and writers locked and explicitly reports exclusions; it does not claim full disaster recovery.
- The writer identity can upload bounded, checksum-verified versions and read only manifests. It cannot read archived document bytes or delete versions. The separate proposed retention identity cannot read, write or decrypt private documents. Existing web identity validation stays unchanged.
- Production readiness requires both archive and retention source watermarks, warns at ten minutes and blocks new acceptance at twelve. Missing/wrong-release/stale heartbeats fail closed. Alert failures are reported separately without aborting paid-obligation maintenance. The missing retention-capability name in the Railway web preservation list was reported and corrected. Independently run readiness, intake and operations tests passed 33/33.
- Independent peer review found that current-inventory absence alone could cause the read-only planner to propose removing a still-required historical object, and that old-manifest proposals could include the last recovery mapping. The planner now preserves every version. Object retention mapping and a verified replacement checkpoint remain explicit unresolved inputs; proposed removals are empty. Regression tests cover absent, superseded, held and last-manifest cases.
