# Prepared Railway AWS caller identity

Status: local implementation prepared. No hosted trust anchor, role, profile, certificate, secret or provider verification was performed by this work. The local credential-runtime image installs and checks the pinned helper without credentials or AWS calls; that packaging check is not hosted identity proof. Target account `838445019912` and region `us-east-1` must be verified before an approved change set is applied. Staging and production require separate CA/leaf material, trust anchors, profiles and caller roles. Production permission is a separate human approval.

## Concrete artifacts and boundaries

`infra/aws/roles-anywhere/template.json` prepares the environment-specific trust/profile/caller role. Both trust and profile default disabled. The trust constrains the Roles Anywhere service principal, exact source account/anchor and leaf subject CN. The profile lists only its caller role and requests one-hour sessions; the IAM role also has a one-hour maximum. CloudFormation models for [TrustAnchor](https://docs.aws.amazon.com/AWSCloudFormation/latest/TemplateReference/aws-resource-rolesanywhere-trustanchor.html) and [Profile](https://docs.aws.amazon.com/AWSCloudFormation/latest/TemplateReference/aws-resource-rolesanywhere-profile.html) informed these resources; actual provider validation is still required.

`scripts/prepare-aws-roles-anywhere.mjs` takes three absolute paths: a reviewed nonsecret target manifest, a **public CA certificate**, and a new output directory. It validates the environment/account/region, exact versioned worker, KMS key, and temporary bucket/prefix, then writes a disabled template with a concrete least-privilege caller permissions boundary plus `review.json`. It makes no provider calls and authorizes no mutation. Manifest fields are `deploymentEnvironment`, `accountId`, `region`, `workerVersionArn`, `kmsKeyArn`, `kmsKeyVersion`, `temporaryBucket`, `temporaryPrefix` (`ephemeral/`), and `caCertificateSha256` (DER SHA-256). No default real resource IDs are invented. A missing public CA or exact target blocks preparation of a final resolved artifact.

The caller gets only exact-version Lambda invocation, temporary-prefix object put/get/delete, and the exact KMS key with application/deployment/key-version context. The document-worker stack's existing runtime policy is attached and intersected with this caller boundary. Review its current policy document before approval. This is separate from the Lambda execution role and its network/object permissions. No human provisioning permissions are granted here; the authorized operator uses separately reviewed scoped provisioning/recovery access. Existing broad human permissions must not be removed before replacement access is proven.

## Runtime integration

The explicit `awsWorkloadCredentials` provider is exported from `src/lib/security/aws-workload-credentials.ts` (runtime wrapper) and `scripts/lib/aws-roles-anywhere.mjs` (Node bootstrap). `src/lib/security/aws-kms.ts` supplies it to the KMS client, and `src/lib/files/aws-document-worker.ts` supplies it to both S3 and Lambda clients using one resolved environment. The durable deletion client in `src/lib/files/aws-temporary-cleanup.ts` uses the same explicit provider and exact environment bucket; see `LAUNCH_MAINTENANCE_CLEANUP.md` for its persisted obligations and readiness holds. These clients set explicit regional AWS HTTPS endpoints; the bootstrap's STS identity check also sets its regional endpoint and explicit temporary credentials. Missing/mixed deployment identity and alternate credential/endpoint/TLS overrides are rejected without the SDK default chain. KMS requires the configured key account to match `APP_AWS_ACCOUNT_ID`; the worker requires the pinned account, version ARN and exact environment bucket.

`src/lib/security/remote-kms.ts` requires AWS for both hosted staging and production. Its legacy remote adapter is available only when explicitly selected in development/test with no deployment marker. The readiness wrapper validates sealed leaf/CA/key binding and expiry locally, then KMS readiness performs a real synthetic provider round trip when identity configuration is valid. Source wiring and local negative tests do not prove actual hosted credentials, STS identity or permissions; those checks remain required before use.

Required names are in `.env.example` and `.railway/launch-contract.ts`: `APP_AWS_ACCOUNT_ID`, `APP_AWS_RA_DEPLOYMENT_ENV`, `APP_AWS_RA_TRUST_ANCHOR_ARN`, `APP_AWS_RA_PROFILE_ARN`, `APP_AWS_RA_ROLE_ARN`, `APP_AWS_RA_HELPER_PATH`, `APP_AWS_RA_CERTIFICATE_SHA256`, `APP_AWS_RA_CA_CERTIFICATE_SHA256`, and the three base64 PEM values `APP_AWS_RA_CERTIFICATE_PEM_BASE64`, `APP_AWS_RA_PRIVATE_KEY_PEM_BASE64`, `APP_AWS_RA_CA_CERTIFICATE_PEM_BASE64`. Base64 is encoding, not encryption: enter the leaf values through the provider's sealed-secret flow into the exact named service. Do not place their values in logs, manifests, Git or receipts. No CA private key belongs in Railway, this repository, a helper process or a deployment artifact.

The leaf must match its private key and pinned public CA, have exact subject `CN=applypack-<environment>-railway-caller`, be an end-entity certificate valid for at most 30 days, and retain more than 65 minutes of validity. Pin both DER fingerprints in the reviewed configuration. The provider checks these conditions before each refresh. It creates mode-0700 directories and mode-0600 leaf files only on Linux x86-64 `/dev/shm` verified as tmpfs, removes them after helper success/failure, and clears its temporary buffers. The sealed source remains in process environment memory; restart the service after rotation. Abrupt process death may leave tmpfs files until container teardown, so prove exclusive service/container ownership and teardown cleanup. No promise of secure erasure from memory is made.

`scripts/install-aws-signing-helper.mjs /usr/local/bin/aws_signing_helper` is a root-only Linux x86-64 build preparation command. It reads only `/opt/applypack-helper-input/aws_signing_helper`, copied from the pinned source-build stage, and verifies the reviewed SHA-256 in `SIGNING_HELPER` before writing a new root-owned executable. It rejects a symlink, writable/unowned input, unexpected size or digest, and an existing output. There is no download, variable hash or vulnerable-binary fallback. Runtime must use a non-root UID; the provider requires a root-owned helper and ancestor directories with no group/other write permission or symlinks, preventing the caller from replacing verified helper bytes.

The earlier official AWS 1.8.5 binary failed the strict image scan with six High findings. Its receipt remains historical. The replacement is an ApplyPack security rebuild of exact AWS source commit `08f7df47e6da0b58c0e5960c41f5d3601042b1d2`, with patched supported Go and a reviewed dependency-only update; it is not an AWS-published or AWS-signed binary. `infra/aws/roles-anywhere-helper/` supplies the pinned build inputs and common preparation/compilation procedure. Two clean builds reproduced version `1.8.5+applypack.1`, SHA-256 `6bc6af3a10ff0894a552a9a40c414436d0cb91e422262b10e85af61f619d9c9b`, with 22 offline checks passing in each build and zero High/Critical helper findings. Future changes require the same reproducibility, regression and strict scan evidence before changing the runtime pin. Whole-image clearance remains a separate required receipt. The image retains upstream/dependency licenses and actual binary module/build provenance under `/usr/share/applypack/signing-helper/`; detailed source/module-authentication evidence stays outside the runtime. Current build and scan receipts determine validation status; this runbook supplies no hosted identity proof. AWS documents the preserved [credential-process interface](https://docs.aws.amazon.com/rolesanywhere/latest/userguide/credential-helper.html).

Each refresh verifies helper bytes, uses direct arguments without a shell, requests 3600 seconds, bounds execution/output, validates temporary credential expiry, and calls regional STS `GetCallerIdentity` with those explicit credentials. Only the exact environment caller role/account is accepted. Refresh is shared across concurrent callers and starts five minutes before expiry; failed refresh clears the cache and returns a generic failure without provider output or secret values.

## Ownership, rotation, revocation and alert evidence

All human owners remain **UNASSIGNED**: certificate issuance, offline CA custody/recovery, leaf rotation, revocation/CRL publication, expiry alerts, provisioning and incident response. Assign actual people before enabling a trust/profile. The prepared template is not authorization to create a CA or issue a certificate.

Issue leaves through the approved offline CA workflow with no more than 30-day validity. Rotate before expiry, verify new leaf/key/DER fingerprints, seal them into the exact environment, deploy locked, and prove the new identity before revoking the old leaf. Separate environment CA fingerprints are a reviewed operational requirement; do not reuse one environment's trust material in the other.

Run `node scripts/check-aws-roles-anywhere-expiry.mjs` from the protected service environment. Exit 0 means the locally validated certificate has more than seven days remaining; exit 2 means rotation is due; exit 1 means validation failed. The output is sanitized and explicitly says `providerVerified=false`. Connect exits 1/2 to the approved external alert route and prove delivery to primary/backup responders. No alert destination or human acceptance is invented by this artifact.

Revocation requires the approved CA/CRL and Roles Anywhere revocation process or disabling the exact profile/trust anchor. Record the decision, actor and actual provider outcome. Existing temporary credentials can continue to work for their remaining lifetime; the one-hour setting is a bound, not immediate revocation. Measure actual denial at refresh, existing-session behavior and fail-closed behavior under helper timeout, missing binary, hash mismatch, expired leaf, bad CA, wrong role and blocked STS. Never substitute static AWS keys when refresh fails.
